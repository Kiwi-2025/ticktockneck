# 第二梯队性能优化 — 设计说明

日期：2026-10-20
状态：已实现

## 背景

第一梯队（`2026-10-20-perf-tier1-design.md`）解决了启动速度和几个界面卡顿问题，
但没有动进程结构 —— 常驻内存仍是 250MB 上下。本梯队目标是压内存、减少开机打扰，
并顺手收掉一些零散的小问题。

## 实测基线（第一梯队之后）

| 状态 | 总内存(WS) |
|------|------------|
| 主窗口可见 | 287 MB |
| 主窗口隐藏（渲染进程还活着） | 287 MB |

**隐藏和可见的内存完全一样** —— 一个看不见的 `BrowserWindow` 仍然占着约 62MB 的
渲染进程（Tab 进程），这是最没性价比的一块常驻开销。

## 变更项

### 1. 主窗口隐藏后直接销毁

`main.js` 原来在关闭/最小化时只 `hide()` 窗口。现在改成 `destroy()`：

- 计时状态在**主进程**里，窗口随时可以重建，销毁不丢任何状态；
- `showMainWindow()` 早就有懒创建逻辑，销毁后点托盘图标会重新建一个；
- 顺带解决了一个隐患：隐藏的窗口仍会收到 IPC、仍占用 GPU 合成资源。

代价：每次从托盘打开要多一次窗口创建 + 页面加载（约 200~400ms）。对这种
「大部分时间待在托盘」的工具来说，这个取舍是划算的。

关闭事件里用 `setImmediate` 推迟销毁，避免在 `close` 事件处理中重入 `destroy()`。

### 2. 开机自启支持"仅驻留托盘"

新增设置项 **仅驻留托盘**（`config.silentStart`）：

- 勾选后，系统登录项带上 `--hidden` 参数，开机后只建托盘、不建主窗口；
- 启动参数解析在 `main.js` 顶部，`--hidden` 时跳过 `createMainWindow()`；
- 托盘图标点击走 `showMainWindow()`，窗口懒创建 —— 这正是历史上 `--hidden`
  被移除的原因（旧版 `showMainWindow()` 不会创建窗口），现在该逻辑已就位。

`lib/login-item.js` 抽出纯函数 `loginItemArgs({ autoStart, silentStart })`，
把"要不要注册、带不带 `--hidden`"的规则从系统调用里分离出来，可单测。

登录项的迁移逻辑同步调整：旧版本残留的 `--hidden` 条目仍然要清掉，但当用户
**主动**勾选了"仅驻留托盘"时，`--hidden` 属于有意为之，保留不动。

### 3. 零散小项

| 项 | 说明 |
|----|------|
| `spellcheck: false` | Electron 默认开启拼写检查，界面只有两个数字输入框，纯属浪费 |
| `videoUrls()` 缓存 | 视频列表运行期不变，省掉每次弹窗时的一次 `readdirSync` |
| `saveConfig` 去掉冗余读 | 以内存里的 config 为基准合并写，不再每次保存都重读磁盘 |
| `play().catch()` | 弹窗切换视频时 `play()` 的 Promise 可能 reject，补上兜底 |
| `powerMonitor` 睡眠/唤醒 | 睡眠期间挂起的定时器醒来后不一定准时触发，resume 时补一次 tick |

`saveConfig` 保留同步写：文件只有一百来字节，同步的开销可以忽略，而异步反而
可能在退出瞬间丢掉最后一次修改。

## 明确跳过的项

**休息弹窗预建**（提前创建隐藏的弹窗窗口以避开渲染进程冷启动）——**不做**。

- 收益只有约 250ms 的弹窗出现延迟，对一个倒计时到点的提醒来说感知不到；
- 代价是弹窗在活动期就常驻，多占约 70MB，和本轮"压内存"的目标相反；
- 要正确实现还得给视频加"等信号再播放"的闸门（否则视频会提前 10 秒开始放，
  用户错过开头），引入约 40 行新逻辑和一类新的时序 bug。

真要优化弹窗的出现速度，收益更高的方向是"减少用户等待"而不是"提前建窗口"，
当前没有证据表明这里是痛点。

## 影响面

| 文件 | 变更 |
|------|------|
| `main.js` | 隐藏即销毁；`--hidden` 静默启动；登录项同步；`videoUrls` 缓存；`saveConfig` 简化；`powerMonitor`；导出测试钩子 |
| `lib/login-item.js` | 新增：`loginItemArgs` 纯函数 |

| `reminder.js` | `play()` 加 catch 兜底 |
| `test/login-item.test.js` | 新增 4 个单测 |
| `scripts/smoke.js` | 冒烟测试扩展：销毁/重建窗口、静止启动路径 |

## 实测结果

| 指标 | 改动前 | 改动后 |
|------|--------|--------|
| 主窗口可见时内存 | 287 MB | 287 MB |
| **驻留托盘时内存** | 287 MB | **220 MB（-67 MB，-23%）** |
| 弹窗出现延迟 | ~250 ms | ~250 ms（不变，见上） |
| 开机自启弹主窗口 | 是 | 可选「仅驻留托盘」后不再弹 |

## 测试

- `node --test`：27 个用例全绿（23 + 4 个 `loginItemArgs`）。
- `npm run smoke`：16 项全绿（销毁/重建窗口、倒计时新鲜、输入框、暂停/恢复、
  休息弹窗整条链路）。
- `npm run smoke -- --hidden`：4 项全绿（静默启动不建窗口、托盘点击能拉起窗口）。
- 冒烟测试耗时从第一梯队的 ~90s 降到 ~25s：不再等满一分钟的活动期（改成把
  计时器快进），窗口改走真实的 close 路径而不是直接 hide。
